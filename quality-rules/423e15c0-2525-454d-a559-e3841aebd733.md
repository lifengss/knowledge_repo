# 测试用例完整度

## 规则描述

测试用例应包含完整的测试项目描述，覆盖正常流与异常流，并明确每一步的输入、动作与期望结果：

- **given**：前置条件、输入数据或环境状态
- **when**：执行的操作或触发的动作
- **expect**：期望看到的效果或输出
- **异常流**：不仅要说明异常场景，还需明确**期望的处理方式**

## 检查项

- [ ] 每个测试用例包含清晰的项目描述
- [ ] 正常流包含 given / when / expect 三要素
- [ ] 异常流包含具体的异常场景说明
- [ ] 异常流包含明确的期望处理方式（如报错信息、降级策略、状态回滚等）

## 示例

### 符合规范

```text
描述：用户提交空表单时的校验
given：用户已进入提交页面且未填写任何字段
when：用户点击“提交”按钮
expect：系统提示“请填写必填项”，表单未提交
异常流：网络超时情况下，系统展示“提交失败，请稍后重试”，并保留用户已填内容
```

### 不符合规范

```text
描述：用户提交空表单
given：未填写字段
when：点击提交
expect：提示错误
异常流：网络超时
```
